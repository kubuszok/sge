## Command semantics (source-verified)

- `--pg-conf` is repeatable; files parse in command-line order
  (R8Command.Builder.addProguardConfigurationFiles appends to an ArrayList) —
  merge order is therefore controlled by argument order.
- R8 default mode is RELEASE (R8Command.Builder.defaultCompilationMode();
  OPPOSITE of D8, whose default is --debug). Default output mode DEX, default
  output path ".", default --min-api 1 → ALWAYS pass --min-api explicitly.
- `--lib` accepts android.jar/rt.jar OR a JDK home dir (detected via
  lib/jrt-fs.jar, JdkClassFileProvider) — CompilerCommandParserUtils.java.
- d8.jar contains full R8 (AOSP external/r8 Android.bp builds d8 and r8 from
  identical r8-src; R8.class present in the build-tools jar) → no separate
  artifact needed when driving from build-tools.
- Canonical invocation: `java -cp r8.jar com.android.tools.r8.R8 --release
  --min-api <n> --output out --pg-conf proguard.cfg --lib <android.jar> input.jar`.
- Version drift: 8.6.2 has --desugared-lib-pg-conf-output (gone from main);
  main adds --api-database, --build-metadata-output. Hidden accepted flags:
  --optimize-multidex-for-linearalloc, --dumpinputtofile, --dumpinputtodirectory.
  Plan must pin a version and not assume flag stability across build-tools.
- Standalone R8 on Google Maven: com.android.tools:r8, latest release 9.1.31
  (2026-03-20); prebuilt r8lib.jar at
  https://storage.googleapis.com/r8-releases/raw/<version>/r8lib.jar —
  a Maven-pinned R8 (reproducible) is available as an alternative to the
  build-tools -dev builds.

## Addendum 2 (2026-07-01): Scala 3 + reflection pitfalls (VERIFIED, cited)

- Canonical Scala rules: `-dontwarn scala.**` + `-keepclassmembers class * { ** MODULE$; }` + keep main (ProGuard manual, guardsquare.com/manual/configuration/examples); fullest community set: scala-android/sbt-android resources/android-proguard.config (+ -dontwarn scala.reflect./scala.concurrent./scala.beans.ScalaBeanInfo, -keepattributes SourceFile,LineNumberTable,Signature). AGP>=8: missing classes are hard errors; R8 writes suggested rules to missing_rules.txt.
- Scala 3 lambdas (LambdaMetafactory.altMetafactory, always-serializable): desugar fine at any min-api (R8 LambdaDescriptor.java; verified vs scala3 3.3.6 BackendUtils.scala).
- KEY PITFALL: `$deserializeLambda$`/scala.runtime.LambdaDeserialize is DELETED by D8/R8 (LambdaDeserializationMethodRemover) — lambda serialization silently broken on Android; NO keep rule fixes it.
- StringConcatFactory: moot on Scala 3.3 LTS (target 8 StringBuilder); D8 desugars indy concat anyway; classfile-output R8 may need -dontwarn java.lang.invoke.StringConcatFactory.
- Fixed R8 Scala bugs to know: b/223424356 (VerifyError, interface-array checkcast removal, fixed 2022-05, commit 8ec45a23), b/140267001 (covariant-return bridge casts, 2019), b/130783484 (MethodHandle.invoke needs --min-api 26 — satisfied at minSdk 26).
- Full mode (R8 default, no --pg-compat): reflection-only classes need explicit -keep; default ctor NOT implicitly kept; -keepattributes only applies to kept items; InnerClasses/EnclosingMethod need both endpoints kept. R8 only models reflection with CONSTANT args (ReflectionOptimizer + -identifiernamestring); non-constant → manual keeps.
- Practical Scala 3.3 load-bearing set: -dontwarn scala.** (or targeted from missing_rules.txt), -keepclassmembers { ** MODULE$; }, -keepattributes Signature,InnerClasses,EnclosingMethod where generics introspected, keeps for structural-type/Class.forName targets. PanamaPort reflection keeps come from its own AAR consumer rules.

## Addendum 3 (2026-07-01): AGP rule generation + merge semantics (VERIFIED, cited)

- proguard-android-optimize.txt is NOT a static resource: generated by AGP ProguardFiles.java concatenating proguard-header.txt + variant middle + proguard-common.txt (jar resources under com/android/build/gradle/); fragments byte-identical across AGP 8.11.2/8.13.2/9.2.1. The $ANDROID_HOME/tools/proguard copy is obsolete and ignored.
- Only functional diff android.txt vs android-optimize.txt today: -dontoptimize vs -allowaccessmodification. The generated files contain REAL rules (keepattributes x7, native methods, View setters, Activity onClick, enum values/valueOf, Parcelable CREATOR, JavascriptInterface, legacy @Keep, -dontwarn androidx.**).
- Merge semantics: rules from ALL sources are UNION/ADDITIVE; NO documented ordering/precedence ("Keep rules are additive—they are merged from all sources"). So --pg-conf argument order does NOT create precedence — a library's global flag (e.g. -dontoptimize) hits the whole app through AGP 8.x.
- AGP 9.0: drops getDefaultProguardFile("proguard-android.txt") (contains -dontoptimize) AND filters global options out of library consumer rules. Banned-for-libraries list: -include -basedirectory -injars -outjars -libraryjars -repackageclasses -flattenpackagehierarchy -allowaccessmodification -renamesourcefileattribute -ignorewarnings -addconfigurationdebugging -printconfiguration -printmapping -printusage -printseeds -applymapping -obfuscationdictionary -classobfuscationdictionary -packageobfuscationdictionary. RECOMMENDATION for the sbt plugin: filter these from AAR consumer proguard.txt like AGP 9 does.
- Targeted consumer rules (AGP>=3.6): META-INF/com.android.tools/r8-from-<X>-upto-<Y>/ in AAR classes.jar (fallback: proguard.txt, META-INF/proguard/).

## Addendum 4 (2026-07-02): R8-specific rules — MAJOR PREMISE CORRECTION

- "-alwaysinline removed in ~8.2" is FALSE: no removal commit exists in the r8 repo; parses in the regular parseOption() chain 8.2→main and IS applied (feeds alwaysInline set in RootSetBuilder). Empirically exit 0 on 8.2.47, 8.6.2 (build-tools 35), 8.13.19. Caveat: undocumented/unsupported officially. Confusion source: -neverinline/-alwaysclassinline etc. are TESTING options gated by -Dcom.android.tools.r8.allowTestProguardOptions=true (hard error otherwise).
- PanamaPort R8Annotations = io.github.vova7878:R8Annotations:v1.0.1 (NOT machinezoo). Its AAR consumer proguard.txt (-alwaysinline on @AlwaysInline, -checkdiscard on @CheckDiscard, -assumenosideeffects for @NoSideEffects, -keepclassmembers,...,includecode for @KeepCode) runs on standalone R8 8.13.19 with exit 0, only Info "Ignoring modifier: includecode" x2. -checkdiscard is ENFORCED (build fails if item survives) but vacuous under --no-tree-shaking. Rules would break only Guardsquare ProGuard.
- Unknown-option taxonomy (ProguardConfigurationParser.java, main): silently ignored: -optimizations -dontpreverify -verbose -dontusemixedcaseclassnames -overloadaggressively …; Info: -optimizationpasses; warned: -outjars -addconfigurationdebugging -assumenoexternal*; hard error: -skipnonpubliclibraryclasses and any truly unknown option.
- -assumenosideeffects supported (removes call when return unused/const-propagatable; does NOT substitute defaults like ProGuard -assumevalues). compatibility-faq.md does not mention it (earlier citation premise false).
- Diagnostics: -printusage/-printseeds/-printconfiguration optional filename (stdout default; printconfiguration adds per-file provenance); -whyareyoukeeping = full class-spec, stdout only, NO OUTPUT under -dontshrink. AGP outputs: build/outputs/mapping/<variant>/{usage,seeds}.txt + configuration.txt.
- Q4 empirical (citation pending): SDK_INT>=minApi dead-branch elimination happens even in plain D8 and --debug; backporting is a desugaring feature; BackportedMethodList → 109 backports at min-api 26.

### aapt2 link --proguard [LOCAL, build-tools 35.0.0]

- Flags confirmed in local `aapt2 link --help`: `--proguard <file>`,
  `--proguard-main-dex <file>`, `--proguard-conditional-keep-rules`,
  `--proguard-minimal-keep-rules`, `--no-proguard-location-reference`.
  Source of truth: Link.h
  <https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/tools/aapt2/cmd/Link.h>
  (developer.android.com/tools/aapt2 has a copy-paste doc bug on
  --proguard-conditional-keep-rules — its text describes --proguard-main-dex).
- Real output (manifest: application/activity/service/receiver; layout:
  custom view + android:onClick):
  ```
  # Referenced at AndroidManifest.xml:4
  -keep class com.example.app.MainActivity { <init>(); }
  # Referenced at res/layout/main.xml:4
  -keep class com.example.app.CustomView { <init>(...); }
  # Referenced at res/layout/main.xml:5
  -keepclassmembers class * { *** onButtonTap(android.view.View); }
  ```
  Manifest components always `{ <init>(); }` (no-arg ctor), unconditional.
  `--proguard-minimal-keep-rules` narrows layout views to
  `<init>(android.content.Context, android.util.AttributeSet)`.
  `--proguard-conditional-keep-rules` prefixes layout-only classes with
  `-if class **.R$layout { int main; }` (manifest rules stay unconditional).
  Generator: ProguardRules.cpp
  <https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/tools/aapt2/java/ProguardRules.cpp>.
  DataBinding rules do NOT come from aapt2. AGP always passes --proguard,
  --proguard-main-dex, --proguard-minimal-keep-rules,
  --no-proguard-location-reference (AaptV2CommandBuilder.kt) and feeds
  build/intermediates/aapt_proguard_file/<variant>/aapt_rules.txt into R8
  (ProguardConfigurableTask.kt, tools/base mirror-goog-studio-main).

### min-api features: shrinking mode vs --no-tree-shaking vs plain D8 [LOCAL]

Test: `if (Build.VERSION.SDK_INT >= 26) "branch-new" else "branch-old-dead"`,
both branches verified present in input bytecode (javap).

| Pipeline | dead branch eliminated? |
|---|---|
| R8 --release --min-api 26 (full shrinking) | YES |
| R8 --release --min-api 26 --no-tree-shaking --no-minification | YES |
| D8 --release --min-api 26 | YES |
| D8 --debug --min-api 26 | YES |
| D8 --release --min-api 21 (control: branch live) | no (both kept) |

- Conclusion: **SDK_INT >= minApi dead-branch elimination requires NO
  shrinking mode — plain D8 does it in every mode**; it is min-api driven.
- Backported method rewriting: desugaring feature (D8 and R8, all modes);
  `com.android.tools.r8.BackportedMethodList --min-api N` ships in the same
  d8.jar (109 entries at api 26, 2 at api 34) [LOCAL].
- API outlining (`ExternalSyntheticApiModelOutline*`, soft-verification-error
  avoidance for calls above min-api): **UNVERIFIED** — research agent did not
  return citations; training knowledge says D8 and R8 both do API modeling
  since ~R8 8.0/AGP 8.0; verify before the plan relies on it.
- Shrinking-only semantics: `-whyareyoukeeping` emits NOTHING under
  -dontshrink [WEB]; `-checkdiscard` is VACUOUS under --no-tree-shaking
  (passed despite item present in dex, dexdump-verified) [LOCAL].
